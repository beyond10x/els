An action such as `metrics.inspect` must reach one concrete system (one cluster, one namespace,
through one tool) without the protocol ever naming that tool. Decision record 0083 splits the path
into four layers, each named once.

## Four layers

| Layer | Example | Owner | Changes per deployment? |
|---|---|---|---|
| Action (protocol, tool-agnostic) | `metrics.inspect`, `logs.search` | ELS | no |
| Capability (semantic, scoped) | `metrics.read{cluster: prod-eu, namespace: foo}` | the protocol declares it; the case grants it | no |
| Data contract | `series/v1alpha1`, `logs/v1alpha1` | Connectors | no |
| Connection | one metrics store, one log store | the operator, in the Connectors catalog | yes |

The rule: no layer above the connection names a tool.

## Capabilities

A protocol action declares the capability it needs. Today that is a name:

```yaml title="protocols/incident-response/1.yaml (excerpt)"
actions:
  release.rollback:
    effect: write
    requires:
      - capability: release.rollback
```

Canon decides nothing about who holds it: whoever runs an evaluation passes in which capabilities are
granted or denied, and an action is admissible only when every capability it requires is granted.
Decided but not yet built: capabilities carry a scope, a case holds scoped grants derived from its
subject, and the precedence is deny over require-approval over allow, with nothing granted by
default.

## Bindings

For each invocation, right before it acts, Commission resolves capability → data contract →
connection from the operator's catalog, narrowed by the case's current grant. The catalog entry
format is still open; a sketch:

```yaml title="catalog sketch (illustrative, format open)"
deployment: prod-eu
capabilities:
  metrics.read:
    contract: series/v1alpha1
    connection: metrics-prod-eu
    scope_keys: [cluster, namespace]     # what a grant may narrow on
  logs.read:
    contract: logs/v1alpha1
    connection: logs-prod                # another deployment binds another log store
    scope_keys: [cluster, namespace]
  topology.read:
    contract: resource_discovery/v1alpha1
    connection: cluster-prod-eu
    scope_keys: [cluster]
```

## Enforcement, top to bottom

| Check | Where |
|---|---|
| The action is admissible now | Canon |
| The granted capability covers the requested scope | Commission, before it invokes |
| The query stays inside the scope | the Connectors adapter, by native query containment |
| The credential cannot reach beyond the scope | narrowed credentials, later |

The model never sees connection names or credentials. It sees `metrics.inspect` with arguments whose
schema carries no scope fields it could change.
